# MYBOOK format support

Версия профиля: 1.16.11

## Ready for use

DOCX character styles: `DocxDocumentReader` читает стили WordprocessingML типов `paragraph` и `character` из `word/styles.xml`, разрешает `basedOn` и применяет `w:rPr/w:rStyle@w:val` к отдельным фрагментам DOCX. Итоговое оформление вычисляется в порядке приоритетов `paragraph style` → `character style` с его `basedOn` → `direct run rPr`. Поддерживаются `w:b`, `w:i`, `w:u`, `w:strike`, `w:vertAlign` (superscript/subscript); явные `w:val="0"`, `w:u w:val="none"` и прямое `w:vertAlign` задают свойства текущего run без влияния на следующие runs. Каскад действует в обычных абзацах, `w:hyperlink`, `w:fldSimple`, таблицах, headers, footnotes, tab/break text. Идентификатор отсутствующего или несимвольного `w:rStyle`, невалидный `w:pStyle`, цикл или отсутствующий `basedOn` character style и ссылка на parent style другого типа вызывают `InvalidDataException`. Отдельная автономная DOCX regression проверяет наследование, приоритет direct rPr, выключение оформления, HTML anchor links, все перечисленные контейнеры и диагностику ошибок. Regression suite выполняется с `--no-books` без доступа к папке Books.

DOCX OPC core properties: `DocxDocumentReader.ReadCoreProperties` читает `dc:title` и `dc:creator` из единственного core-properties part, на который указывает корневая связь `_rels/.rels` c Type `http://schemas.openxmlformats.org/package/2006/relationships/metadata/core-properties` или ECMA-376 `http://schemas.openxmlformats.org/officedocument/2006/relationships/metadata/core-properties`. `DocumentModel.Title` получает очищенный по краям `dc:title` либо имя DOCX без расширения, если связь или название отсутствует; `DocumentModel.Author` получает `dc:creator` либо пустую строку. `cp:lastModifiedBy` не используется вместо автора. Target разрешается относительно корня ZIP по правилам OPC, с поддержкой root-relative путей, percent-encoded UTF-8 и литерального `%` через `%25`. Внешние/повторные связи, отсутствующие части, query/fragment, некорректные percent escapes, выход за корень архива, неподдерживаемый TargetMode и неверный XML root/дубли dc:title/creator вызывают `InvalidDataException`. Reader не читает `docProps/core.xml` без root relationship. Синтетические DOCX regression fixtures проверяют оба relationship types, Unicode paths, title/author и отсутствие метаданных, fallback к имени файла и повреждённые связи/свойства без доступа к каталогу Books.

DOCX numbering sequences: `DocxDocumentReader` читает реальные последовательности `numbering.xml` из `abstractNum/lvl` и отдельных экземпляров `num`, учитывая `start`, `num/lvlOverride/lvl`, `startOverride` и `lvlRestart`. `startOverride` имеет приоритет над `start` вложенного `lvl`. При отсутствии `lvlRestart` более глубокий уровень перезапускается после использования непосредственно предыдущего уровня; `lvlRestart=0` запрещает перезапуск, а положительное значение задаёт one-based уровень триггера. Счётчики независимы для каждой пары `partPath/numId` и уровня `ilvl`; списки в основной части, таблицах, headers/footers и сносках используют соответствующие последовательности. Повторное использование header/footer part в другой секции заново начинает нумерацию его экземпляра, не влияя на основной текст. `lvlText` подставляет фактические номера ранее использованных уровней в `%1`…`%9`, сохраняя формат каждого уровня: `decimal`, `decimalZero`, `upperLetter`, `lowerLetter`, `upperRoman`, `lowerRoman`; `bullet` отображает исходный маркер, `none` не добавляет текстового префикса. `numId=0` означает отсутствие маркера. Неполные или противоречивые определения, некорректные диапазоны уровней, шаблоны и переполнение вызывают явную диагностическую ошибку; неподдерживаемые виды `numFmt` возвращают `NotSupportedException`. Регрессия DOCX синтетически проверяет независимые instances, multi-level numbering, w:start/lvlOverride/startOverride, Roman/letter/decimalZero, отсутствие явного start, none, lvlRestart, сквозную нумерацию в таблицах, независимость header/footnote, повторно используемые headers и malformed XML. Форматный regression suite выполняется с `--no-books`, не открывая каталог `Books`.

DOCX hierarchical outlines: `DocxDocumentReader` формирует `DocumentModel.Outlines` из заголовков основного `word/document.xml` в порядке документа. Встроенные paragraph styles `Heading1`…`Heading9`, их потомки через `basedOn`, явный `w:pPr/w:outlineLvl` и `w:style/w:pPr/w:outlineLvl` определяют уровни 1–9; `outlineLvl` 0–8 означает Heading1–9, 9 — явное отсутствие заголовка и блокирует наследование. Прямой уровень абзаца имеет приоритет над стилем. Оглавление вложено по ближайшему предыдущему меньшему уровню; пропуски уровней не порождают вымышленных записей. Source `bookmarkStart@name` задаёт `TargetAnchorId`, а заголовкам без bookmark выделяются стабильные `docx-heading-N` без конфликтов с любыми bookmark names в документе. Заголовки в таблицах, колонтитулах, сносках и пустые заголовки не входят в outline. Неподдерживаемые `outlineLvl` отклоняются `InvalidDataException`. Синтетические DOCX regression fixtures проверяют структуру, Word styles, наследование, source/synthetic anchors, HTML-переходы и invalid levels. Общий набор регрессий запускается с `--no-books`, без обращения к каталогу Books.

FB2 section outlines: `Fb2DocumentReader` формирует `DocumentModel.Outlines` из `title` основного `body` и вложенных `section`, сохраняя порядок исходных глав и их родительско-дочернюю иерархию. Названия из нескольких `title/p` объединяются с нормализацией whitespace и сохраняют текст inline formatting; исходные `title@id`, `section@id`, `body@id` служат `TargetAnchorId`. Для заголовков без доступного ID создаются воспроизводимые `fb2-heading-N`; все source XML IDs зарезервированы, чтобы synthetic anchors не конфликтовали с ними, включая ID, встречающиеся позднее в документе. Вложенные sections без собственного `title` не создают пустых пунктов, а их озаглавленные дочерние sections доступны в ближайшем существующем уровне. `body name="notes"` и декоративные `poem`/`epigraph` titles не создают outline entries; сами блоки продолжают читаться. Автономная FB2 regression проверяет дерево, отдельные body, collisions, deterministic anchors и наличие целевых HTML-якорей. Регрессионный suite запускается с `--no-books`, без обращения к `Books`.

EPUB OPF manifest URI paths: `EpubDocumentReader.ResolveManifestPath` разрешает относительные URL/URI в `manifest/item@href` относительно каталога OPF, проверяет percent-encoded пары шестнадцатеричных символов и декодирует UTF-8 percent escapes перед поиском ZIP entry. Одни и те же правила используются для XHTML spine, foreign spine fallback paths, EPUB3 navigation, EPUB2 NCX и `cover-image`. Символ `+` не интерпретируется как пробел, `%25` преобразуется в один литеральный `%`; ссылки из навигации и из XHTML приводятся к тем же внутренним путям. Некорректные percent escapes, внешние URL и manifest href с query/fragment дают `InvalidDataException`. Regression создаёт EPUB только во временном каталоге: проверяет имена с пробелами, UTF-8, escaped percent, XHTML/CSS/image, cover и nav/NCX. Общие тесты запускаются в режиме `--no-books` без обхода каталога Books.

EPUB 3 OPF spine manifest fallback: для foreign `itemref` reader разрешает цепочку атрибутов `manifest/item@fallback` по IDREF до первого XHTML (`application/xhtml+xml`) и использует этот документ как главу в исходном порядке spine. XHTML-главы открываются напрямую без обхода их fallback-цепочек. Ссылки оглавления и внутри глав на исходный foreign resource направляются к якорю соответствующей XHTML-главы. Недостающие `itemref@idref` или manifest IDs, отсутствующий XHTML fallback и циклы возвращают `InvalidDataException` с конкретной диагностикой. Проверки форматов запускаются с `--no-books`: этот режим исключает `Book library fixture layout` и `Supported corpus smoke`, не обращаясь к каталогу Books. Синтетические EPUB fixtures создаются только во временной директории тестов.

PDF ToUnicode и Type0 Encoding CMap codespacerange: `PdfCMapCodeSpace` определяет длину source code по первому подходящему диапазону от 1 до 4 байт; каждый байт проверяется по соответствующей паре нижней/верхней границ. `PdfFontDecoder` и `PdfCidMap` выбирают длину независимо от наличия `bfchar`/`bfrange` либо `cidchar`/`cidrange` mapping. Отсутствующий Unicode mapping внутри codespace даёт один U+FFFD на весь character code, код вне объявленных ranges вызывает `InvalidDataException`; CID lookup без mapping возвращает false без сдвига позиции. Недопустимые размеры и обратные границы codespacerange отклоняются. Для CMap без codespacerange сохраняется декодирование по mapping lengths. Regression покрывает mixed 1/2-byte codes, 3/4-byte ranges, bytewise boundaries, missing codes, malformed declarations и полный PDF reader. Примеры реального корпуса `Books/Work` используют одно- и двухбайтовые CMap, оставаясь вне Git.

PDF ToUnicode и Type0 Encoding CMap: лексеры поддерживают PostScript metadata dictionaries `<< ... >>` (включая вложенные словари) и literal strings `(...)` с вложенными/escaped скобками. Содержимое `CIDSystemInfo` не воспринимается как hex mapping: `codespacerange`, `bfchar`, `bfrange`, `cidchar` и `cidrange` разбираются по своим операторам. Несогласованные `<<`/`>>`, незакрытые literal strings и некорректные hex-цифры вызывают `InvalidDataException`. Regression включает CMap parsing и полный PDF reader с `/ToUnicode`. Личные PDF из `Books/Work` не становятся versioned corpus fixtures.

Проверочные EPUB2, EPUB3 и Word 97 binary документы `Regression_*` находятся в `Tests/Fixtures` и читаются regression suite по явным путям. Книжный корпус `Books` содержит `Books/Ветхий Завет` для отдельных книг Ветхого Завета; `Books/bibliya.fb2` остаётся отдельным полным изданием. Corpus smoke рекурсивно обходит книжный каталог, исключая пользовательскую папку `Books/Work`, и не включает тестовые fixtures.

RTF table-style row identity/banding: `irowN`, `irowbandN` и parameterless `lastrow` сохраняются отдельно в `DocumentTableStyleRowFormatting.RowIndex`, `BandIndex` и `IsLastRow` как nullable source metadata. Числовые controls требуют signed Int32, включая `irowband-1` для header band и граничные значения Int32; `lastrow` задаёт `true` без numeric parameter. Отсутствие каждого control сохраняет `null`, explicit zero остаётся 0, повторные `irow`/`irowband` используют последние значения. Base и conditional `tsN` entries, nested destinations, style geometry и body rows независимы; row identity каталога не применяется к body и не экспортируется как HTML body row metadata.

RTF table-style look flags: все 11 parameterless `tbllkborder`, `tbllkshading`, `tbllkfont`, `tbllkcolor`, `tbllkbestfit`, `tbllkhdrrows`, `tbllklastrow`, `tbllkhdrcols`, `tbllklastcol`, `tbllknorowband` и `tbllknocolband` сохраняются как nullable `DocumentTableStyleRowFormatting.Look` с типом `DocumentTableLook`. Присутствующий flag даёт `true`, отсутствующий — `null`, а полностью отсутствующий набор — `null Look`. Numeric parameters отклоняются. Повторные flags не меняют source presence; base/conditional entries с одинаковым `tsN` и nested destinations независимы. Body `DocumentTable.Look` и HTML metadata вычисляются исключительно из body row controls; table-style look не применяется к body table и не эмулирует автоформатирование.

RTF table-style indentation: `tblindN` и `tblindtypeN` сохраняются в `DocumentTableStyleRowFormatting.Indent` как nullable source `Value` и `Unit` без body defaults. Unit 0 (Auto) и 2 (Nil) не задают derived величину; unit 1 (dxa/twips) даёт `Points = Value / 20`, unit 3 (pct) — `Percent = Value / 50` только при наличии обоих source параметров. Неизвестный unit сохраняется без интерпретации, incomplete declarations остаются nullable, повторные controls используют последнее значение. Numeric parameters обязательны и допускают signed Int32. Base/conditional entries, nested groups и body tables независимы; stylesheet indentation не применяется к body layout.

RTF table-style positioning/wrapping сохраняется в `DocumentTableStyleRowFormatting.Positioning` как source metadata: horizontal frames `tphcol/tphmrg/tphpg`, placements `tposx/tposnegx/tposxc/tposxi/tposxo/tposxl/tposxr`, vertical frames `tpvmrg/tpvpg/tpvpara`, placements `tposy/tposnegy/tposyt/tposyil/tposyb/tposyc/tposyin/tposyout`, text distances `tdfrmtxtLeft/Right/Top/Bottom` и parameterless `tabsnoovrlp`. Nullable frames, source position kinds, signed Int32 twips и computed points сохраняют отличие отсутствующего control от явного значения 0; в отличие от body `DocumentTablePositioning` не выставляются effective defaults. Повторные positions используют последнее значение, flags очищают предшествующий numeric offset на своей оси. Неверные параметры отклоняются. Conditional styles сохраняют независимые позиции; catalog не применяется к body и не выполняет visual wrapping.

RTF outer row padding table styles: `trpadot/trpador/trpadob/trpadol` и `trpadoft/trpadofr/trpadofb/trpadofl` представлены в `DocumentTableStyleRowFormatting.OuterPadding` как source measurements по четырём сторонам крайних ячеек таблицы. `Value` и `Unit` nullable и сохраняются независимо; unit 0 означает Null/fallback к `trgaph`, unit 3 — twips и points (`value / 20`). Неизвестные units и отсутствующие numeric parameters отклоняются, repeated controls используют последние values, conditional style entries не перезаписывают base entry. Catalog formatting не применяется к body таблицам.

RTF table-style outer row cell spacing сохраняет `trspot/trspor/trspob/trspol` и units `trspoft/trspofr/trspofb/trspofl` в `DocumentTableStyleRowFormatting.OuterCellSpacing`. В отличие от внутреннего `CellSpacing`, эти source values относятся к внешним краям первой/последней строки и крайних столбцов таблицы. Каждая из четырёх сторон содержит nullable `Value`, `Unit`, `Points`: unit 0 означает Null, unit 3 — twips с conversion в points, а отсутствующий value или unit остаётся null. Требуются numeric параметры signed Int32; units кроме 0/3 отклоняются. Повторные controls используют последнее значение, conditional style entries независимы, stylesheet не влияет на body spacing.

RTF table-style row cell spacing сохраняет `trspdt/trspdr/trspdb/trspdl` и соответствующие `trspdft/trspdfr/trspdfb/trspdfl` в `DocumentTableStyleRowFormatting.CellSpacing` без вычисления table-style cascade. Для каждой стороны сохраняются nullable `Value`, `Unit`, `Points`: unit 0 = Null (spacing игнорируется), unit 3 = twips (points = value/20). Значение и единица могут присутствовать по отдельности, repeated controls сохраняют последние source значения. Numeric controls обязательны к параметризации signed Int32, unit принимает только 0 или 3. Conditional entries не перезаписывают base entry и не влияют на body table row spacing.

RTF table-style direction: `taprtl` сохраняет nullable `TableRightToLeft` (`true` только при явном flag) отдельно от nullable row-cell `RightToLeft`, задаваемого `rtlrow` (`true`) и `ltrrow` (`false`). Без controls оба свойства остаются `null`; последнее `rtlrow/ltrrow` определяет source row direction. Все flags требуют отсутствия numeric parameter. Base и conditional table-style entries имеют независимые direction values; nested destinations и catalog formatting не влияют на body table direction.

RTF `stylesheet` сохраняет table-style row layout в `DocumentTableStyleRowFormatting`: nullable `Alignment` (`trql/trqc/trqr`), nullable `AutoFit` (`trautofit0/1`), `RepeatAsHeader` (`trhdr`), `PreventPageSplit` (`trkeep`) и `KeepWithNext` (`trkeepfollow`). Контрольные слова валидируются по source grammar, повторный alignment использует последнее значение. Каталог не применяет formatting к body.

RTF table-style row geometry: `trleftN`, `trgaphN` и `trrhN` сохраняются независимо в `DocumentTableStyleRowFormatting` как source twips и nullable points. `trgaph` обозначает половину межъячеечного интервала, `trrh0` — auto height, положительный `trrh` — minimum height, отрицательный — exact height. `HeightExact` остаётся null без `trrh`; отрицательная высота переводится в положительные points с сохранением signed twips. Numeric parameters требуют signed Int32; переполнение и minus без цифр приводят к `InvalidDataException`. Style geometry не влияет на body rows.

MYBOOK считает готовыми к обычному пользовательскому чтению все форматы,
которые присутствуют в `SupportedFormatRegistry`:

| Расширение | Профиль поддержки |
| --- | --- |
| `.fb2` | FictionBook 2: метаданные, body, текст, структура, таблицы, ссылки, anchors и встроенные изображения. |
| `.epub` | EPUB 2/3: package/manifest/spine, XHTML, CSS/resources, изображения/SVG, navigation/NCX, landmarks/page-list и note semantics. |
| `.html`, `.htm` | Локальный HTML открывается напрямую через изолированное virtual-host mapping WebView2. |
| `.txt` | Обычный текст как preformatted document. |
| `.md` | Markdown через фиксированный Markdig pipeline с advanced extensions. |
| `.rtf` | Основной RTF reading profile: Unicode/codepages, explicit Unicode alternative `\upr`/`\ud` selection (text/bookmarks/hyperlink results) with strict group validation, font-level `cpg`/`fcharset` mappings, formatting, links/fields, tables/nesting, raster/vector pictures с byte-exact `\binN` для `pict` (raw braces/backslashes/CRLF сохраняются; смешение с hex не допускается), Symbol/Mac/DBCS/PC/OEM charsets; custom tabs `tx`, bar tabs `tb`, `tlmdot` middle-dot и другие leaders сохраняются в нейтральной модели и HTML metadata. Required `\line` сохраняется внутри paragraph как line break; `\page`, `\column` и `\sect` сохраняются как отдельные Page/Column/Section `DocumentFlowBreak` блоки. Nonrequired `\softline` хранится отдельным inline soft break, а `\softpage`/`\softcol` — как Page/Column blocks с `IsSoft`; HTML экспортирует `soft-line-break`/`flow-break-soft` metadata. `\softlheightN` сохраняется в точной позиции как signed `DocumentInline.SoftLineHeight` и экспортируется HTML `data-soft-line-height`; значение не трактуется как twips/CSS line-height без отдельной galley/layout модели. Block breaks внутри table явно unsupported до table-pagination layout. Unicode special-character controls `\emspace`/`\enspace`, `\ltrmark`/`\rtlmark`, `\zwj`/`\zwnj`, а также типографские dash/quote/bullet controls сохраняются как точные Unicode code points без ASCII fallback. RTF fields сохраняют cached `\fldrslt`; `HYPERLINK`, `PAGE`, `NUMPAGES`, `DATE`, `TIME`, `REF`, `PAGEREF`, `NOTEREF` получают `DocumentFieldKind`, normalized `\fldinst` и target metadata без пересчёта значения. Unsafe hyperlink target не становится `href`; неизвестные/исполняемые fields остаются plain saved result. Automatic `\chftn{\footnote...}` поддерживается с отдельными footnote/endnote counters, `\ftnstart`/`\aftnstart`, `\ftnalt`, superscript anchors/links и note-tail blocks; field/text formatting внутри note проходит общий parser. Custom notes без `\chftn` привязываются к последнему Unicode-символу перед `\footnote`: исходный mark/style сохраняется как ссылка на note anchor и не расходует automatic counter. Custom mark внутри field/hyperlink inline, tables внутри notes, page/section restart и non-Arabic marker formats остаются explicit unsupported при фактическом использовании. Document-level `\fet`, placement (`\endnotes`/`\enddoc`/`\ftntj`/`\ftnbj`, endnote equivalents), `\ftnstart`/`\aftnstart`, restart и все документированные footnote/endnote numbering controls сохраняются в `DocumentNoteSettings` как neutral metadata. `\ftnsep`/`\ftnsepc`/`\ftncn` и endnote equivalents сохраняют formatted paragraph blocks вне body; `\chftnsep`/`\chftnsepc` остаются точными anchor markers без выдуманного glyph. HTML экспортирует note settings в `data-note-*`, а separator destinations — в inert `<template>`. Character revision tracking сохраняет ordered Unicode `revtbl`, `\revised`/`\deleted`, insertion/deletion author+32-bit DTTM, formatting revisions `\crauth`/`\crdate` и move marks `\mvf`/`\mvt` + `\mvauth`/`\mvdate` как `DocumentRevisionMark`; group scope и `\plain` сбрасывают revision character properties. HTML экспортирует `data-revision-*` metadata, не скрывая deleted text и не принимая изменения. Paragraph-property revisions `\prauth`/`\prdate` сохраняются в `DocumentParagraph.PropertyRevision`, table-row revisions `\trauth`/`\trdate` — в `DocumentTableRow.PropertyRevision`; author index разрешается через `revtbl`, DTTM сохраняется raw+decoded. `\pard` и `\trowd` сбрасывают соответствующий revision state, nested table rows сохраняют собственные metadata; HTML экспортирует `data-paragraph-revision-*` и `data-row-revision-*`. ## Чтение и настройки типографики

Вкладка **Settings → Чтение** задаёт базовую типографику всех reader-backed потоковых форматов (`.fb2`, `.epub`, `.txt`, `.md`, `.rtf`, `.doc`, `.docx`) и сохраняет параметры в `%LOCALAPPDATA%\\MYBOOK\\settings.json` через `AppSettings.ReadingTypography`. Типизированный `DocumentReadingTypography` поддерживает шесть явных шрифтовых семейств (`Georgia`, `Segoe UI`, `Arial`, `Times New Roman`, `Verdana`, `Consolas`), базовый размер 12–36 CSS px, ширину reader content 480–1400 CSS px и line-height 110–250%. Neutral defaults: `Georgia`, `19px`, `980px`, `1.62`, совпадающие с базовой HTML-типографикой предыдущих версий. Неизвестное имя шрифта и числа вне допустимого диапазона отклоняются явной ошибкой без эвристических fallback. Старый JSON без `ReadingTypography` получает нейтральные defaults; сохранённый объект с некорректными значениями не замещается автоматически.

Окно настроек предлагает WPF preview, восстановление defaults без записи и отдельную кнопку Apply для сохранения. После закрытия окна настроек `MainWindow` применяет сохранённые CSS variables к уже открытому сгенерированному flow document через `DocumentHtmlRenderer.CreateTypographyScript`, без повторного чтения файла. Обновление целиком отделено от `WebView2.ZoomFactor` и переключения цветовой темы. Рендерер использует `body.flow-document` только для reflow documents без fixed-page блоков: source `DocumentInline.FontFamily`/`FontSizePoints` и другие inline/paragraph styles остаются неизменными и имеют приоритет над inherited базовой типографикой. PDF/DjVu SVG/fixed-page layout и пользовательский локальный HTML (`.html`/`.htm`, открываемый напрямую в WebView2) не получают reflow overrides. Значения CSS fonts формируются только из фиксированного enum, числовые значения проверяются и форматируются инвариантно; JavaScript arguments проходят JSON encoding. В обоих заголовках приложения отображается актуальная assembly version, синхронизированная с `MYBOOK.csproj`. Регрессия проверяет presets/defaults, JSON round-trip, CSS/JS, независимость source formatting/fixed pages и отказ на invalid values.

## Позиции чтения документов

MYBOOK сохраняет **последнюю вертикальную координату прокрутки** отдельно для каждого поддерживаемого файла: сгенерированные потоковые страницы, fixed-page PDF/DjVu/IW44 и пользовательский локальный HTML/HTM. `ReadingPositionService` использует ключ `Path.GetFullPath` и Windows case-insensitive сравнение; каждая запись `DocumentReadingPosition` хранит полный нормализованный путь и неотрицательный целочисленный `ScrollTopPixels` (CSS px). При отсутствии записи документ открывается сверху (0); запись с 0 сохраняет явно возвращённое пользователем начало. История ограничена последними 200 разными файлами, при обновлении позиция переносится в начало; исходный документ не редактируется.

`MainWindow` подписывается на `CoreWebView2.NavigationStarting`, `NavigationCompleted` и `WebMessageReceived`. После успешной навигации ожидаемого URI `DocumentReadingPositionScript.CreateInstallScript` восстанавливает `window.scrollTo({left:0,top:position,behavior:"instant"})` и подписывает страницу на `scroll` с debounce 350 ms, `pagehide` и `visibilitychange`. JavaScript сообщения `mybook-reading-position-v1` принимаются только от активного main-frame URI (scheme/host/path/query совпадают, а fragment `#anchor` допускается) с точным GUID сеанса и валидным Int32 scroll offset; поздние события прошлой книги, другие протоколы и malformed JSON не изменяют историю. Повторное открытие reader-backed книги выполняет explicit `CoreWebView2.Navigate` даже при том же временном `book.html`. Перед переключением книг приложение читает актуальный `document.scrollingElement.scrollTop` через `ExecuteScriptAsync`, а перед закрытием окна выполняет асинхронный flush; при ошибке записи пользователь выбирает остаться в приложении либо закрыть его без последней позиции. Незавершённая первоначальная навигация не записывает фиктивный offset. Прямой локальный HTML получает только runtime scroll listener, без изменения исходного файла, его CSS или virtual-host security mapping.

Позиции записываются в `%LOCALAPPDATA%\\MYBOOK\\settings.json` как `AppSettings.ReadingPositions`; `AppSettingsStore` валидирует абсолютность и нормализованность путей, отсутствие дубликатов и диапазон координат, а обновления выполняет через JSON во временном файле и атомарную замену. Старые настройки без `ReadingPositions` получают пустой список; malformed сохранённые записи не заменяются эвристическими значениями. История остаётся независимой от WebView2 ZoomFactor, сохранённой типографики и DocModel. Текущая координата — **абсолютное смещение в CSS px**: после изменения ширины окна, размера шрифта или reflow она не гарантирует сохранение того же текстового абзаца; структурные bookmarks/anchors и относительное положение внутри fixed-page остаются отдельными направлениями разработки.

Regression suite проверяет запись/восстановление независимых EPUB/PDF/HTML путей, JSON round-trip и migration, точный нулевой offset, ограничение 200 документов, отказ на malformed data/token/JSON и generation/capture JavaScript; отдельный Node.js execution smoke проверяет восстановление, debounce, pagehide, visibilitychange, повторную установку и смену токена. Интерактивное визуальное тестирование реального WPF/WebView2 UI в эти проверки не входит.

## DjVu fixed-page profile

`.djvu` и standalone legacy `.iw4` зарегистрированы в `SupportedFormatRegistry` как reader-backed fixed-page formats и используют `DjvuDocumentReader`. Reader проходит общий `DocumentInputGuard`, разбирает container, рендерит каждую поддерживаемую страницу в opaque RGB PNG с учётом source initial display mode и создаёт `DocumentFixedPage` с physical point/native pixel geometry, selectable text-zone overlay, maparea annotations, page presentation/metadata и outline navigation. Общий HTML/SVG renderer, WebView2 viewport scaling, боковая плёнка страниц, переходы `page-N`, Ctrl+F, recent documents и file associations работают через существующую инфраструктуру MYBOOK.

`DjvuContainerReader.Inspect` проверяет `AT&T`, `FORM:DJVU`/`FORM:DJVM` и legacy `FORM:PM44/BM44`, big-endian chunk lengths, odd-byte padding, nesting/resource limits. `FORM:DJVU` требует первым chunk `INFO`; поддерживаются legacy 5-byte `INFO` (width/height/minor version) и current 10-byte `INFO` (major/minor version, raw DPI, gamma, rotation flags). Standalone/bundled/indirect `FORM:PM44/BM44` являются legacy one-page IW44 images: geometry берётся из первого PM44/BM44 chunk, native image geometry является page geometry, DPI равен 100 и initial rotation отсутствует — это соответствует DjVuLibre. У legacy IW44 page нет source `INFO`: `DjvuPageInfo` не синтезирует INFO version/gamma, а codec major/minor и grayscale flag сохраняются в `DjvuIw44Sequence`. Legacy 5-byte `INFO` metadata также не дополняется синтетическими DPI/gamma/rotation значениями; fixed-page layout при отсутствии DPI использует один layout point на raster pixel, не меняя source metadata.

Visual profile включает:
- standalone/full-page JB2 `Sjbz` с local, bundled или indirect shared `Djbz`; local page dictionary имеет приоритет, иначе используется первый `Djbz`, найденный рекурсивно по ordered `INCL` graph;
- regular non-striped `Smmr` mask;
- progressive IW44 `BG44`/`FG44` и legacy full-page `PM44`/`BM44` с serial/slice/version/color/geometry validation и общим managed inverse-wavelet decoding; legacy sequences всегда используют native geometry (`subsample=1`), допускают PM44/BM44 chunk IDs в одной sequence как DjVuLibre, а grayscale определяется IW44 header flag, не именем FORM;
- JPEG `BGjp`/`FGjp`;
- `FGbz` version 0 RGB palette с BZZ per-blit color indexes;
- compound composition из одного `Sjbz`/JB2 или `Smmr` mask, optional `BG44`/`BGjp` background и optional `FGbz`/`FG44`/`FGjp` foreground colors; source display modes `color` (полный composite), `fore` (цветной foreground по бинарной маске поверх белого), `back` (только исходный BG44/BGjp) и `bw` (бинарная mask) выбирают точные raster paths до PNG encoding, включая INFO rotation; режимы без обязательной mask/background отклоняются явно;
- `INFO`-only pages и pages только с известными nonvisual chunks (`INCL`, `ANTa`/`ANTz`, legacy `FORM:ANNO`, text, `METa`/`METz`) создают opaque white surface с final `INFO` rotation; page-level chunks вне реализованного profile сохраняются отдельно и блокируют blank fallback;
- DjVu 4-bit linear scaling для reduced backgrounds, integral nearest-neighbor expansion для reduced foreground color rasters и final `INFO` rotation.

`DIRM` v1 поддерживает bundled и indirect metadata, component roles, IDs, names и titles. Bundled offsets/sizes/roles сверяются с реальными FORM types: page role принимает `FORM:DJVU`, `FORM:PM44` и `FORM:BM44`, shared roles — `FORM:DJVI`, thumbnail role — `FORM:THUM`. Для indirect DJVM `DjvuIndirectDocumentResolver` загружает `DJVU`/`PM44`/`BM44` page components и shared components относительно каталога index-файла: physical filename берётся из DIRM `Name`, если он присутствует, иначе из component `Id`, а `INCL` и NAVM продолжают разрешаться по component ID. Shared `FORM:DJVI` может рекурсивно включать другие shared components; dependency graph сохраняет `INCL` order, использует cache, ограничивает глубину/resources и явно отклоняет cycles. Rooted/path-traversal names, отсутствующие files, DIRM size mismatch и role/FORM mismatch отклоняются. Каждый `DjvuImageChunk` хранит собственный `SourcePath`, поэтому raster decoders читают payload непосредственно из page/shared component и не принимают index path. Суммарный объём реально открываемых external page/shared files ограничен 256 MiB.

BZZ `NAVM` разбирается в bounded recursive outline. Internal page references используют DjVu resolution order ID → signed relative displacement → TITLE → page number → NAME; relative targets разрешаются относительно содержащей страницы. External HTTP/HTTPS/mailto URLs остаются внешними. Outline передаётся в `DocumentOutlineItem` и использует общую навигацию MYBOOK.

`ANTa` и BZZ-compressed `ANTz` проходят strict UTF-8 validation. Legacy `FORM:ANNO` внутри `FORM:DJVU` или `FORM:DJVI` содержит последовательность вложенных `ANTa`/`ANTz` IFF chunks, которые декодируются тем же parser через `DjvuAnnotationChunkReader`: binary FORM body проверяется по big-endian lengths, odd-byte padding, nested count и точному исходному порядку. Формы ANNO располагаются до standalone ANTa/ANTz внутри своего компонента по legacy DjVuLibre semantics; отдельный FORM может быть пустым. Неизвестные дочерние chunks (включая FORM) явно отклоняются, а не трактуются как реализованные annotations. Per-form limit составляет 4 MiB payload и 128 child chunks; per-component — 32 legacy forms, 128 total annotation chunks, 16 MiB decoded UTF-8, per-chunk — 1 MiB encoded/decoded. Для standalone, bundled и indirect DJVM `INCL` сохраняет порядок вложенных и обычных аннотаций; общий IFF resource budget включает все children. Реальных legacy FORM:ANNO в текущем локальном corpus не найдено; synthetic regression включает страницы/общие компоненты, ANTa + BZZ ANTz, malformed stream и full reader/HTML path.

Единый bounded S-expression parser разбирает mapareas и top-level page annotations после рекурсивного разворачивания shared `INCL` в исходном decoder order. Для `background`, `zoom`, `mode` и `align` действует last-expression-wins; `metadata` объединяется с last-value-wins по key; XMP сохраняет первый непустой payload по semantics `DjVuANT::merge`. Поддерживаются `background #RRGGBB`, zoom `default`/`page`/`width`/`one2one`/`stretch`/`d1..d999`, mode `default`/`color`/`fore`/`back`/`bw`, horizontal/vertical `align`, quoted metadata values, `xmp` и print-only `phead`/`pfoot`. `DocumentFixedPagePresentation` сохраняет effective hints, metadata и XMP. Surrounding `background` применяется как CSS custom property; source `mode` выбирает фактический PNG raster в `DjvuDocumentReader`, а initial `zoom` и `align` формируют индивидуальную viewport-поверхность каждой страницы через CSS. `page` использует viewport fit с сохранением aspect ratio, `width` — доступную ширину reader content, `one2one` — исходную ширину raster в CSS pixels, `stretch` — обе оси viewport с `preserveAspectRatio=none`, `dNNN` — N процентов от physical point width в CSS pixels (96/72). Горизонтальное/вертикальное выравнивание применяется внутри page-scoped flex viewport; normal pages без hints сохраняют исходную layout-разметку. Пользовательский `WebView2.ZoomFactor` остаётся независимым множителем масштаба, не перезаписывается hints и продолжает управляться кнопками/Ctrl+wheel/Ctrl+0. Безопасные `data-*` отражают effective zoom/mode/alignment, metadata count и XMP-presence marker; raw metadata/XMP не внедряются в HTML.

Page-local DjVu `METa` и `METz` — отдельные от `ANTa` `(metadata ...)` и `(xmp ...)` источники метаданных. `METa` сохраняет точные bytes, `METz` проходит bounded BZZ decoding; `DjvuPageInfo.MetadataChunks` и `DocumentFixedPagePresentation.SourceMetadataChunks` сохраняют упорядоченные записи `(Kind, Data)`. Формат содержимого не интерпретируется как S-expression, текст или XML без отдельной спецификации: бинарные bytes (включая не-UTF-8) сохраняются без guess-based conversion, а в HTML выводится только `data-source-meta-chunk-count`. Chunk bounds: 1 MiB compressed/input и 1 MiB decoded на запись, 128 записей и 4 MiB decoded на страницу, 16 MiB decoded на весь документ, включая все indirect DIRM page components. Пустой `METa` сохраняется; пустой `METz` отклоняется как некорректный BZZ stream. Синтетический end-to-end regression проверяет BZZ decompression, binary payload, разделение `METa/METz` и `ANTa`, IFF order, page isolation, отдельный тест границы 16 MiB для indirect DIRM pages, resource limits, blank-page rendering и отсутствие raw payload в HTML. В доступных локальных real DjVu fixtures `METa/METz` не обнаружены, поэтому поддержка подтверждена DjVuLibre source semantics и синтетическими fixtures.

Legacy DjVu 3 print-only annotations `(phead "...")` и `(pfoot "...")` содержат от одной до трёх quoted strings в точном формате `left::text`, `center::text`, `right::text`. Парсер сохраняет каждую позицию отдельно, различает отсутствующую позицию и пустой текст, отклоняет повтор позиции, неизвестное имя позиции, неверное число аргументов и неquoted значения. Повторные `phead` и `pfoot` независимо используют последнее целое expression в порядке ANTa/ANTz и shared `INCL` merge. `DocumentFixedPagePresentation.PrintedHeader/PrintedFooter` сохраняют значения для вывода на печать: HTML содержит три экранированных spans внутри print-only header/footer вне SVG image, по умолчанию они скрыты `display:none`; `@media print` размещает их в трёхколоночном CSS grid с исходным left/center/right выравниванием. Print annotations не изменяют экранный raster, source zoom, selectable text, ссылки и не внедряют raw HTML. Известные malformed `phead/pfoot` завершаются ошибкой.

Vendor-specific и неизвестные DjVu annotation expressions не получают предположительной интерпретации. `DjvuAnnotationReader` сохраняет точное имя и область каждого неизвестного выражения: `TopLevel`, `MapAreaShape` или `MapAreaOption`. В `ANTa`/`ANTz` и shared `INCL` merge диагностические записи сохраняют исходный порядок, без содержимого неизвестного payload. Неизвестная shape не создаёт ложную интерактивную область; неизвестная option не влияет на известные visual properties той же maparea; недопустимая известная option продолжает завершаться ошибкой. Для каждой annotation chunk действует лимит 10 000 неизвестных выражений, после merge — 100 000. `DocumentFixedPagePresentation.UnrecognizedAnnotations` сохраняет записи для анализа; `ParserTrace` и HTML `data-unrecognized-annotation-count` выводят только количество. Имена и raw payload не внедряются в HTML, поэтому расширения с HTML-подобными именами не исполняются. Для реальной реализации нового vendor-specific behavior нужны документация расширения и подтверждающий fixture.

Reader разбирает все пять стандартных `maparea` shapes: `rect`, `oval`, `poly`, `text` и `line`, сохраняет optional `(url href target)` metadata и точную bottom-left pixel geometry. Visual profile maparea поддерживает `none`, `xor`, `border`, `shadow_in/out/ein/eout`, `border_avis`, rectangular `hilite` + `opacity` (0–100, default 50), line `arrow`/`width`/`lineclr` и text `backclr`/`textclr`/`pushpin`; повторные известные options применяются последовательно с last-value-wins. Colors принимаются только как `#RRGGBB`; option, применённая к недопустимой shape, завершается явной ошибкой. Fixed-page renderer сохраняет decorative mapareas с пустым URL, рисует XOR через white stroke + `mix-blend-mode:difference`, solid/hover/always borders, shadow modes через CSS inset/outset/groove/ridge, highlights с source opacity, colored lines и optional arrow marker, а text notes — через XHTML `foreignObject`; pushpin использует нативный `details/summary` без JavaScript. Размер arrow marker и font/layout text note определяются renderer-ом, поскольку DjVu source задаёт наличие arrow и цвета/область текста, но не отдельные arrowhead/font metrics.

`TXTa` и BZZ-compressed `TXTz` извлекают strict UTF-8 page text. Version-1 text-zone tree разбирает PAGE/COLUMN/REGION/PARAGRAPH/LINE/WORD/CHARACTER geometry и UTF-8 byte ranges. `DjvuTextOverlayBuilder` берёт terminal zones без дублирования parent ranges, сохраняет исходные UTF-8 gaps между соседними zones, строго отклоняет split-codepoint/overlap boundaries и создаёт transparent `DocumentFixedTextRun` overlay. Непустые OCR zones могут выходить за `INFO` bounds, как допускает DjVu text model: координаты не clamp-ятся и не отбрасываются, а SVG viewport скрывает внешнюю часть; interactive maparea geometry остаётся строго page-bounded. Общий SVG renderer использует точную zone width через `textLength/spacingAndGlyphs`, top-aligned geometry, INFO rotation и `user-select:text`; последовательность run text точно восстанавливает `DocumentFixedPage.Text`. Ctrl+F не перехватывается fullscreen hotkey и передаётся WebView2 с включёнными browser accelerator keys.

Resource limits ограничивают file/chunk/nesting/dependency counts, annotation token/depth/chunk counts, legacy FORM:ANNO count/size/child/decompressed-byte budgets, parsed ANTa metadata/maparea counts, METa/METz decoded payload/chunk/page/document bounds, unrecognized annotation expression count, unrecognized page chunk count, decoded BZZ/IW44/JB2/blank raster sizes, shapes/blits/comments, page count, суммарный indirect component input и PNG payload fixed-page model. Неизвестные page chunks не принимаются за blank image; неизвестные/конфликтующие visual layer families, duplicate local `Djbz`, cyclic/too-deep shared dependency graphs, striped `Smmr`, malformed known annotations и недопустимые значения завершаются явной ошибкой вместо частичного рендера.

Regression покрывает container/DIRM/NAVM/text/annotation parsing, legacy FORM:ANNO/ANTa/ANTz nested order и malformed/resources checks для standalone/bundled/indirect DjVu, top-level background/zoom/mode/alignment/metadata/XMP merge semantics, DjVu 3 print-only phead/pfoot parsing/merge и screen-hidden/print-only HTML с entity escaping, page-local METa/METz binary/BZZ metadata preservation и safe HTML count, scoped diagnostics неизвестных top-level/maparea-shape/maparea-option expressions, ANTa/ANTz order, resource limit и HTML safety, active page-scoped zoom/align для всех пяти zoom kinds и native/physical CSS geometry, pixel-accurate foreground/background/BW source display modes и reader → mode-specific PNG, все пять стандартных maparea shapes и visual options, visual-only empty-URL annotations, hover/always borders, hilite opacity, line color/arrow, text pushpin, bundled/indirect nested shared dependencies и cycle rejection, external `SourcePath` binding, local-vs-included JB2 dictionary precedence, JPEG/IW44/JB2/Smmr decoding, FGbz, compound composition, reader → `DocumentModel` → PNG/text/annotation/presentation → HTML/SVG, rotation geometry, out-of-page OCR zones, UTF-8 boundaries, traversal/role/size errors и malformed input. Синтетический regression с последовательными ANTa и BZZ-сжатым ANTz проверяет полный `reader → DocumentFixedPagePresentation → @media print HTML` для phead/pfoot, включая наследование footer, replacement header и безопасное экранирование HTML-like текста. В расширенном локальном наборе 26 успешно разобранных DjVu-документов / 503 страниц с 165 annotation chunks не обнаружено ни реальных phead/pfoot, ни неизвестных extension expressions; эти paths проверяются отдельно по DjVu 3 specification и синтетическим ANTa/ANTz fixtures, а не заявляются подтверждёнными real corpus. Основной real validation corpus содержит 7 корректных DjVu файлов / 147 страниц; четыре legacy fixtures с некорректным UTF-8 внутри `TXTz` завершаются строгой `InvalidDataException`, без producer-specific byte fallback. Дополнительно real `boy_jb2.djvu`, подключённый как external page через indirect DIRM index, проходит полный reader/render path. Real bundled `czech.djvu` проходит 85-page reader/render: 83 text-bearing pages, 49 areas, 30 XOR borders, metadata на всех 85 страницах и `background #8F8F8F` на трёх страницах; HTML содержит ровно три surrounding-background hints и 85 metadata-count markers. Real `vega.djvu` проходит 2/2 pages с `zoom d100` и `mode color`, а `DjVu3Spec_bundled.djvu` — 71/71 pages с `mode color`; neutral model и HTML сохраняют эти значения. Real `navm_fgbz.djvu` проходит 6-page reader/render с 20 XOR areas и 20 corresponding difference-mode SVG borders. `malliavin.djvu` проходит полный reader/render path на 115/115 страницах: 114 text-bearing pages, 2 visual-only empty-URL rect areas с 32-pixel `shadow_in/out`, `hilite #C0FFFF` и default 50% opacity, 30 849 851 bytes encoded PNG. Страница 6 содержит только `INFO` и рендерится как opaque white 2862×4916 surface; HTML содержит два highlights, один inset и один outset visual border. Real legacy fixtures `legacy_pm44.djvu` и `legacy_bm44.djvu` проходят полный one-page reader/render path: PM44 — color IW44 v1.2, 181×240, 100 DPI; BM44 — grayscale IW44 v1.2, 32×32, 100 DPI. Их BGRA32 outputs SHA-256 regression-locked; synthetic bundled и indirect DIRM role-1 fixtures проверяют routing `FORM:PM44` и external `SourcePath`. Real BG44 + Sjbz + FGbz page 10 из `2000_compression_system.djvu` имеет фиксированные SHA-256 для `fore` (`B6FEDDCB33C7E08184226D95DD5BBA5EC2641AB8D36E84ADE9043F0CD669E82F`), `back` (`1D3607977837E155644210162F7B720E99F8C2DAF08B5C7D9E652D53F3D6D2E1`) и `bw` (`1C96524206F2DE57EC70297888E1BAE9A47E9B87BEEF7BAD31108A7C7021BD9B`); synthetic Smmr + BGjp + FGjp проверяет каждый pixel по отдельно декодированным layer/mask и все четыре `mode` через полный reader → PNG. Отдельный registry regression копирует реальный PM44 fixture в `.iw4` и проходит `SupportedFormatRegistry → DjvuDocumentReader → DocumentFixedPage`, поэтому standalone legacy extension доступен через обычный open/file-association path. `BG2k`/`FG2k` не входят в профиль: актуальный DjVuLibre помечает соответствующий JPEG-2000 bitstream как not finalized и не декодирует эти chunks.

## Readiness gates

Перед выпуском профиля выполняются следующие проверки:

- Release build без warnings/errors.
- Полный regression suite.
- Все поддерживаемые файлы из локального `Books` corpus открываются; reader-backed
  документы дополнительно проходят полный `reader -> DocumentModel -> HTML renderer` путь.
- DOC/PDF проходят детерминированный malformed-input набор.
- Входные файлы имеют общий размерный предел; EPUB/DOCX имеют limits на ZIP entries,
  размер распакованных parts и compression ratio.
- XML для FB2/EPUB/DOCX читается без обработки DTD и внешних сущностей и с
  ограничением размера XML.
- RTF nesting и PDF page-tree nesting ограничены.
- Декодированные PDF Flate/LZW/RunLength streams имеют отдельный предел.
- Unsupported конструкции, для которых нельзя гарантировать корректную
  интерпретацию, завершаются явной ошибкой вместо приблизительного рендера.

## Known fidelity limits

Эти пункты не блокируют обычное чтение, но остаются backlog для расширения
совместимости и точности.

### DOCX

- Нет полноценного pagination/page-layout engine; документ читается как flow content.

### DOC

- Редкие list/table style и locale-specific numbering variants.
- Часть редких OfficeArt connector/fill/arrow presets.
- Некоторые header/footer, note, field и section layout semantics требуют
  полноценного pagination engine.
- Legacy Symbol/OEM byte mapping и старые до-Word-97 Binary variants не входят
  в готовый профиль.
- Нет полноценного pagination/page-layout engine.

### RTF

- Редкие row/cell и paragraph controls; row index/banding, last-row marker, table indent units и документированные Word table-look flags для borders/shading/font/color/best-fit, first/last row/column и banding уже сохраняются как metadata.
- Scale без goal-size использует только явно сохранённую PNG/JPEG/BMP physical-density metadata; при её отсутствии размер не угадывается. Bitmap `wbmbitspixel`/`wbmplanes`/`wbmwidthbytes` сохраняются как metadata; `wbitmap`, `macpict` и OS/2 Presentation Manager metafile явно помечены unsupported до появления точных decoder'ов. Отрицательное picture crop-extension пока сохраняется без layout/canvas расширения.
- Font-level `\cpgN` имеет приоритет над `\fcharsetN`. Реализованы все однозначные mappings RTF 1.9.1: ANSI, Mac Roman/Shift-JIS/Hangul/GB2312/Big5/Hebrew/Arabic/Greek/Turkish/Thai/Central European/Cyrillic, Windows Shift-JIS/Hangul/Johab/GB2312/Big5/Greek/Turkish/Vietnamese/Hebrew/Arabic/Baltic/Russian/Thai/Eastern European, PC437 и OEM850. `cpg42` и `fcharset2` используют Symbol private-use mapping. `fcharset1`, старый Mac Johab (`82`) и obsolete Arabic/Hebrew user charsets (`179..181`) без `cpg` отклоняются явно, потому что спецификация не задаёт для них однозначную codepage. Неизвестные charset не наследуют codepage документа. Multibyte decoder не создаёт replacement characters: поддерживаются raw/raw, escaped/escaped, escaped lead + raw trailing byte и escaped lead + escaped special byte; raw lead + escaped trail, incomplete lead и invalid trail отклоняются.
- Некоторые декоративные border styles имеют CSS fallback, а не pixel-identical Word rendering.

### PDF

- PDF Image XObject `/ImageMask true` использует stencil semantics: 1-bit samples с row padding, `/Decode [0 1]` и `[1 0]`, текущий nonstroking RGB color на каждом `Do` и RGBA output с прозрачностью. Для bilevel CCITT/JBIG2 используется их 8-bit decoded sample path. JPXDecode входит в stencil profile только для одного JPEG2000 component с фактической bit depth 1 и без embedded alpha; embedded JPX color mapping отключается, PDF `/BitsPerComponent` может отсутствовать или быть равен 1, а `/Decode [0 1]`/`[1 0]` сохраняет обычную ImageMask polarity. DCTDecode структурно отклоняется, потому что его 8-bit decoded samples несовместимы с обязательной 1-bit ImageMask семантикой. Дополнительные `/Mask` и `/SMask` для stencil отклоняются. Для обычного Image XObject `/Mask` поддерживает explicit ImageMask stream с независимыми Width/Height, собственным `/Decode` и тем же unit-square placement, а также color-key array. Color-key ranges валидируются как 2×N integer boundaries и сравниваются с component samples до PDF `/Decode`; поддержаны 8-bit Gray/RGB/CMYK/CIE/ICC/Separation/DeviceN, packed Indexed 1/2/4/8-bit и bilevel Gray filter output. DCT color-key принудительно проходит через decoded 8-bit samples. JPX color-key использует отдельные integer samples CoreJ2K до 8-bit normalization и индивидуальную JPEG2000 bit depth каждого component; PDF `/BitsPerComponent` для JPX не участвует. Точные ranges поддерживаются для component depths 1..31; 32..38-bit JPX color-key остаётся явным unsupported, поскольку public sample API CoreJ2K возвращает signed `Int32` и не представляет полный unsigned диапазон. `/SMask` и JPX opacity при `/SMaskInData=1/2` имеют приоритет над `/Mask`; при `/SMaskInData=0` embedded opacity игнорируется и не блокирует `/Mask` или current graphics-state soft mask. Собственный `/Mask` заменяет current graphics-state soft mask.
- ExtGState `/SMask /G` входит в профиль для `/S /Alpha` при Identity/default `/TR` и isolated non-knockout transparency group. Mask Form `/BBox` и `/Matrix` валидируются, mask coordinate system использует Form Matrix вместе с CTM, действовавшим в момент `gs`, а `q/Q` и `/SMask /None` сохраняют обычную graphics-state семантику. Fixed-page SVG использует `mask-type:alpha`, clipping по Form `/BBox` и исходный paint order path/Image/Form XObject content. `/BC` не участвует в Alpha mask; Image XObject с собственной `/SMask`, `/Mask` или embedded opacity заменяет graphics-state soft mask для своего `Do`. Вложенные активные ExtGState Alpha soft masks проходят тот же профиль: ExtGState внутри mask group разрешается лениво только при фактическом `gs`, повторное разрешение кэшируется в пределах group extraction, recursive `/G` cycles отклоняются, максимальная глубина — 16 mask groups, отсутствующий nested ExtGState завершается явной structural error. Ordinary Form XObject `Do` внутри Alpha mask group поддерживает optional `/Type /XObject`, `/FormType 1`, обязательный `/BBox`, optional `/Matrix`, наследование текущего graphics state, обязательный BBox clip и полное восстановление состояния после Form content; собственный `/Resources` задаёт изолированный resource context, а при отсутствии `/Resources` named resources разрешаются через Resources страницы. Вложенные ordinary Forms разрешаются лениво, сохраняют единый source paint order, поддерживают собственные ExtGState/Image/Form resources, recursive `Do` cycles отклоняются и nesting ограничен 32 уровнями. `/S /Luminosity`, non-isolated/knockout soft-mask groups, non-Identity `/TR`, text painting, ordinary Form с `/Group`, `/OC` или `/Ref`, а также неизвестные painting operators внутри mask group остаются явным unsupported, чтобы не подменять PDF compositing приближённым браузерным результатом.
- Predefined Type0 CMaps для public Adobe CJK/KR collections входят в профиль: canonical Adobe resources дают code→CID, включая `usecmap` inheritance; без `/ToUnicode` CID→Unicode берётся из canonical `Registry-Ordering-UCS2` mapping resources.
- CIE-based raster ColorSpace `CalGray`, `CalRGB` и `Lab` входят в профиль для 8-bit decoded samples с точными PDF gamma/matrix/Lab transforms и chromatic adaptation к sRGB. `CalGray` DCT входит в профиль через grayscale sample decode; `CalRGB` DCT — при effective JPEG `ColorTransform=1`, с приоритетом Adobe APP14 marker над `/DecodeParms /ColorTransform`. CIE `/SMask /Matte` входит в профиль с unpremultiply в исходных CIE components до gamma/matrix/Lab conversion. `Lab` DCT и `CalRGB` DCT с effective transform=0 поддерживаются через managed BitMiracle.LibJpeg.NET raw-component decoder (JCS_UNKNOWN), который отключает JPEG color conversion, проверяет geometry и ограничивает decoded raster 256 MiB. `ICCBased` `/N=1/3/4` входит в профиль через embedded ICC profile и системный WPF ICC/ICM engine; `/Range` и `/Decode` учитываются строго. ICC Gray/RGB/CMYK DCT post-processing входит в профиль, причём `/N=4` использует decoded CMYK JPEG samples до ICC conversion. `Separation` и `DeviceN` входят в профиль через общий PDF Function evaluator: `FunctionType 2`, sampled `FunctionType 0` с multilinear `/Order=1` и stitching `FunctionType 3`; alternate DeviceGray/DeviceRGB/DeviceCMYK поддерживаются. `FunctionType 4` calculator functions входят в профиль через отдельный VM с полным разрешённым operator set, PDF numeric grammar, 32-bit integer semantics и overflow promotion, PostScript round/bitshift/cvi behavior, синтаксическими conditional expressions для `if`/`ifelse`, top-N output stack semantics, строгими type/stack checks и resource limits. Sampled `FunctionType 0` `/Order=3` входит в профиль через Acrobat-compatible multidimensional cubic interpolation с cubic-convolution `a=-0.5`, quadratic edge handling и recursive interpolation по измерениям. ICCBased, Separation и DeviceN `/SMask /Matte` входят в профиль с unpremultiply в исходных component/tint coordinates до ICC profile conversion или tint transform. DeviceCMYK DCT post-processing входит в профиль через 8-bit CMYK sample decode с geometry validation и последующим PDF `/Decode`. Ненулевой CIE `/BlackPoint` остаётся явным unsupported: PDF использует его при device-dependent CIE gamut mapping, алгоритм которого не задаётся форматом, поэтому fixed sRGB converter не подменяет output device/CMS эвристикой. DeviceN+DCT не заявляется как поддерживаемый: PDF DCT profile ограничен максимум четырьмя components, поэтому произвольный N-channel JPEG не эмулируется.
- CCITT Group 3/Group 4, `JPXDecode` и `JBIG2Decode` входят в профиль. JPX декодируется pure-managed CoreJ2K 2.4.1.108 с geometry/component validation и decoder resource limits; PDF `/BitsPerComponent` и `/Decode` для JPX не используются, явный PDF `/ColorSpace` имеет приоритет над embedded JPX color mapping, а при отсутствии `/ColorSpace` используются embedded Gray/RGB/CMYK semantics. JBIG2 декодируется pure-managed SharpAstro.Jbig2 3.16.981 с optional `/JBIG2Globals`, строгим `/BitsPerComponent 1`, 256 MiB raster limit и обычным PDF `/Decode` после reconstruction. Поддержан arithmetic/MMR surface; Huffman-coded symbol/text variants, custom Huffman tables, MMR внутри pattern/halftone, HENABLESKIP и TPGRON остаются явным unsupported; synthetic SDHUFF regression проверяет NotSupportedException, а PDF adapter сохраняет контекст JBIG2Decode в диагностике. JP2 `cdef` применяется по `Cn`/`Typ`/`Asoc`: color channels формируют canonical порядок `Asoc=1..N`, единственный opacity channel располагается после них. При explicit PDF `/ColorSpace` embedded color mapping CoreJ2K отключён и direct `cdef`/`cmap` one-to-one mapping применяется к raw decoded components в MYBOOK; при implicit ColorSpace тот же canonical порядок формирует CoreJ2K. RGB+alpha покрыт всеми 24 перестановками четырех component indices с сопоставлением manual и embedded mapping, а alpha-first/middle-alpha дополнительно проходят PDF→PNG и `/SMaskInData=2` `/Matte` regressions; Gray+alpha использует ту же association semantics. Один opacity channel может иметь `Asoc=0` для всего изображения либо повторные descriptions по всем color associations. Palette-based `cmap`, shared/unused output channels, unspecified auxiliary channels и несколько opacity channels остаются явным unsupported. JPX с неявным Gray+alpha (два компонента) поддерживает `/SMaskInData=1` и `/SMaskInData=2` с точной Gray `/Matte` compensation; оба варианта покрыты end-to-end regressions. JPX `/SMaskInData=0` (включая default при отсутствии ключа) игнорирует embedded opacity: canonical opacity component исключается из color raster, не создаёт intrinsic mask и оставляет обычный `/Mask` доступным; explicit/implicit ColorSpace и color-key `/Mask` покрыты regression. JPX `/SMaskInData=1` входит в профиль: embedded unassociated opacity извлекается из последнего canonical JPX opacity component и кодируется вместе с цветом в RGBA PNG; поддерживаются явный `/DeviceRGB` и embedded sRGB, а также согласованные компоненты остальных реализованных PDF ColorSpace. Проверяются alpha channel metadata и component counts. JPX `/SMaskInData=2` с preblended colors поддерживается для DeviceGray/DeviceRGB с обязательным `/Matte`: compensation выполняется в исходных цветовых компонентах до RGBA encoding. Для CalGray/CalRGB/Lab и ICCBased компенсация выполняется в исходных компонентах после PDF component decoding и до CIE/ICC преобразования; подтверждены end-to-end CalRGB и ICCBased RGB. Separation и DeviceN также компенсируют tint-компоненты до FunctionType tint transform; end-to-end JPX regressions покрывают Separation/FunctionType 2 и DeviceN/FunctionType 4. Indexed также поддерживает `/SMaskInData=2`: компенсация palette index выполняется до RGB lookup, с проверкой длины `/Matte`; покрыто end-to-end JPX regression.
- Revision 5/6 Unicode passwords проходят SASLprep на фиксированных Unicode 3.2 tables, UTF-8 и truncation до 127 bytes; R6 user/owner authentication использует Algorithm 2.B hardened hash и AESV3. Legacy revisions сохраняют точный byte-password API.
- Password-protected PDF открывается через локализованный password prompt; неверный пароль запрашивается повторно, пароль не сохраняется. R2-R4 string passwords кодируются точным PDFDocEncoding, R5/R6 — SASLprep/UTF-8.
