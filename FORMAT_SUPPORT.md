# MYBOOK format support

Версия профиля: 1.9.1

## Ready for use

MYBOOK считает готовыми к обычному пользовательскому чтению все форматы,
которые присутствуют в `SupportedFormatRegistry`:

| Расширение | Профиль поддержки |
| --- | --- |
| `.fb2` | FictionBook 2: метаданные, body, текст, структура, таблицы, ссылки, anchors и встроенные изображения. |
| `.epub` | EPUB 2/3: package/manifest/spine, XHTML, CSS/resources, изображения/SVG, navigation/NCX, landmarks/page-list и note semantics. |
| `.html`, `.htm` | Локальный HTML открывается напрямую через изолированное virtual-host mapping WebView2. |
| `.txt` | Обычный текст как preformatted document. |
| `.md` | Markdown через фиксированный Markdig pipeline с advanced extensions. |
| `.rtf` | Основной RTF reading profile: Unicode/codepages, formatting, links/fields, tables/nesting, raster/vector pictures, Symbol charset и явно объявленные OEM codepages. |
| `.doc` | Word 97–2003 Binary/CFB reading profile и RTF-файлы с расширением .doc; текст, стили, списки, таблицы, sections, notes, headers/footers, fields, images и поддерживаемый OfficeArt. |
| `.docx` | Word OpenXML flow document: styles, lists, tables, images, relationships, hyperlinks, bookmarks и section metadata. |
| `.pdf` | PDF fixed-page reading profile: classic/xref streams, incremental updates, object streams, text/fonts, paths, images, links/outlines, encryption profiles и поддерживаемые stream filters. |
| `.djvu` | DjVu fixed-page reading profile: single-page `FORM:DJVU`, legacy `FORM:PM44/BM44`, bundled и indirect DJVM containers; JB2/Smmr masks, IW44/JPEG backgrounds/foregrounds, FGbz palettes, compound composition, INFO rotation, NAVM outlines, shared/page ANTa/ANTz mapareas, print-only phead/pfoot, page-local METa/METz source metadata и presentation, selectable TXTa/TXTz text-zone overlay. |
| `.iw4` | Standalone legacy DjVu IW44 image: `FORM:PM44/BM44`, progressive managed IW44 decode, native page geometry и DjVuLibre-compatible 100 DPI; color/grayscale определяется IW44 header flag. |

“Ready for use” означает, что зарегистрированный формат проходит единый путь
от открытия пользовательского файла до модели и итогового рендера, имеет
контролируемый отказ на повреждённом/неподдерживаемом вводе и покрыт
регрессионными fixtures. Это не означает реализацию каждого редкого элемента
соответствующей спецификации.

## DjVu fixed-page profile

`.djvu` и standalone legacy `.iw4` зарегистрированы в `SupportedFormatRegistry` как reader-backed fixed-page formats и используют `DjvuDocumentReader`. Reader проходит общий `DocumentInputGuard`, разбирает container, рендерит каждую поддерживаемую страницу в opaque RGB PNG с учётом source initial display mode и создаёт `DocumentFixedPage` с physical point/native pixel geometry, selectable text-zone overlay, maparea annotations, page presentation/metadata и outline navigation. Общий HTML/SVG renderer, WebView2 viewport scaling, боковая плёнка страниц, переходы `page-N`, Ctrl+F, recent documents и file associations работают через существующую инфраструктуру MYBOOK.

`DjvuContainerReader.Inspect` проверяет `AT&T`, `FORM:DJVU`/`FORM:DJVM` и legacy `FORM:PM44/BM44`, big-endian chunk lengths, odd-byte padding, nesting/resource limits. `FORM:DJVU` требует первым chunk `INFO`; поддерживаются legacy 5-byte `INFO` (width/height/minor version) и current 10-byte `INFO` (major/minor version, raw DPI, gamma, rotation flags). Standalone/bundled/indirect `FORM:PM44/BM44` являются legacy one-page IW44 images: geometry берётся из первого PM44/BM44 chunk, native image geometry является page geometry, DPI равен 100 и initial rotation отсутствует — это соответствует DjVuLibre. У legacy IW44 page нет source `INFO`: `DjvuPageInfo` не синтезирует INFO version/gamma, а codec major/minor и grayscale flag сохраняются в `DjvuIw44Sequence`. Legacy 5-byte `INFO` metadata также не дополняется синтетическими DPI/gamma/rotation значениями; fixed-page layout при отсутствии DPI использует один layout point на raster pixel, не меняя source metadata.

Visual profile включает:
- standalone/full-page JB2 `Sjbz` с local, bundled или indirect shared `Djbz`; local page dictionary имеет приоритет, иначе используется первый `Djbz`, найденный рекурсивно по ordered `INCL` graph;
- regular non-striped `Smmr` mask;
- progressive IW44 `BG44`/`FG44` и legacy full-page `PM44`/`BM44` с serial/slice/version/color/geometry validation и общим managed inverse-wavelet decoding; legacy sequences всегда используют native geometry (`subsample=1`), допускают PM44/BM44 chunk IDs в одной sequence как DjVuLibre, а grayscale определяется IW44 header flag, не именем FORM;
- JPEG `BGjp`/`FGjp`;
- `FGbz` version 0 RGB palette с BZZ per-blit color indexes;
- compound composition из одного `Sjbz`/JB2 или `Smmr` mask, optional `BG44`/`BGjp` background и optional `FGbz`/`FG44`/`FGjp` foreground colors; source display modes `color` (полный composite), `fore` (цветной foreground по бинарной маске поверх белого), `back` (только исходный BG44/BGjp) и `bw` (бинарная mask) выбирают точные raster paths до PNG encoding, включая INFO rotation; режимы без обязательной mask/background отклоняются явно;
- `INFO`-only pages и pages только с известными nonvisual chunks (`INCL`, annotations, text, `METa`/`METz`) создают opaque white surface с final `INFO` rotation; page-level chunks вне реализованного profile сохраняются отдельно и блокируют blank fallback;
- DjVu 4-bit linear scaling для reduced backgrounds, integral nearest-neighbor expansion для reduced foreground color rasters и final `INFO` rotation.

`DIRM` v1 поддерживает bundled и indirect metadata, component roles, IDs, names и titles. Bundled offsets/sizes/roles сверяются с реальными FORM types: page role принимает `FORM:DJVU`, `FORM:PM44` и `FORM:BM44`, shared roles — `FORM:DJVI`, thumbnail role — `FORM:THUM`. Для indirect DJVM `DjvuIndirectDocumentResolver` загружает `DJVU`/`PM44`/`BM44` page components и shared components относительно каталога index-файла: physical filename берётся из DIRM `Name`, если он присутствует, иначе из component `Id`, а `INCL` и NAVM продолжают разрешаться по component ID. Shared `FORM:DJVI` может рекурсивно включать другие shared components; dependency graph сохраняет `INCL` order, использует cache, ограничивает глубину/resources и явно отклоняет cycles. Rooted/path-traversal names, отсутствующие files, DIRM size mismatch и role/FORM mismatch отклоняются. Каждый `DjvuImageChunk` хранит собственный `SourcePath`, поэтому raster decoders читают payload непосредственно из page/shared component и не принимают index path. Суммарный объём реально открываемых external page/shared files ограничен 256 MiB.

BZZ `NAVM` разбирается в bounded recursive outline. Internal page references используют DjVu resolution order ID → signed relative displacement → TITLE → page number → NAME; relative targets разрешаются относительно содержащей страницы. External HTTP/HTTPS/mailto URLs остаются внешними. Outline передаётся в `DocumentOutlineItem` и использует общую навигацию MYBOOK.

`ANTa` и BZZ-compressed `ANTz` проходят strict UTF-8 validation. Единый bounded S-expression parser разбирает mapareas и top-level page annotations после рекурсивного разворачивания shared `INCL` в исходном decoder order. Для `background`, `zoom`, `mode` и `align` действует last-expression-wins; `metadata` объединяется с last-value-wins по key; XMP сохраняет первый непустой payload по semantics `DjVuANT::merge`. Поддерживаются `background #RRGGBB`, zoom `default`/`page`/`width`/`one2one`/`stretch`/`d1..d999`, mode `default`/`color`/`fore`/`back`/`bw`, horizontal/vertical `align`, quoted metadata values, `xmp` и print-only `phead`/`pfoot`. `DocumentFixedPagePresentation` сохраняет effective hints, metadata и XMP. Surrounding `background` применяется как CSS custom property; source `mode` выбирает фактический PNG raster в `DjvuDocumentReader`, а initial `zoom` и `align` формируют индивидуальную viewport-поверхность каждой страницы через CSS. `page` использует viewport fit с сохранением aspect ratio, `width` — доступную ширину reader content, `one2one` — исходную ширину raster в CSS pixels, `stretch` — обе оси viewport с `preserveAspectRatio=none`, `dNNN` — N процентов от physical point width в CSS pixels (96/72). Горизонтальное/вертикальное выравнивание применяется внутри page-scoped flex viewport; normal pages без hints сохраняют исходную layout-разметку. Пользовательский `WebView2.ZoomFactor` остаётся независимым множителем масштаба, не перезаписывается hints и продолжает управляться кнопками/Ctrl+wheel/Ctrl+0. Безопасные `data-*` отражают effective zoom/mode/alignment, metadata count и XMP-presence marker; raw metadata/XMP не внедряются в HTML.

Page-local DjVu `METa` и `METz` — отдельные от `ANTa` `(metadata ...)` и `(xmp ...)` источники метаданных. `METa` сохраняет точные bytes, `METz` проходит bounded BZZ decoding; `DjvuPageInfo.MetadataChunks` и `DocumentFixedPagePresentation.SourceMetadataChunks` сохраняют упорядоченные записи `(Kind, Data)`. Формат содержимого не интерпретируется как S-expression, текст или XML без отдельной спецификации: бинарные bytes (включая не-UTF-8) сохраняются без guess-based conversion, а в HTML выводится только `data-source-meta-chunk-count`. Chunk bounds: 1 MiB compressed/input и 1 MiB decoded на запись, 128 записей и 4 MiB decoded на страницу, 16 MiB decoded на весь документ, включая все indirect DIRM page components. Пустой `METa` сохраняется; пустой `METz` отклоняется как некорректный BZZ stream. Синтетический end-to-end regression проверяет BZZ decompression, binary payload, разделение `METa/METz` и `ANTa`, IFF order, page isolation, отдельный тест границы 16 MiB для indirect DIRM pages, resource limits, blank-page rendering и отсутствие raw payload в HTML. В доступных локальных real DjVu fixtures `METa/METz` не обнаружены, поэтому поддержка подтверждена DjVuLibre source semantics и синтетическими fixtures.

Legacy DjVu 3 print-only annotations `(phead "...")` и `(pfoot "...")` содержат от одной до трёх quoted strings в точном формате `left::text`, `center::text`, `right::text`. Парсер сохраняет каждую позицию отдельно, различает отсутствующую позицию и пустой текст, отклоняет повтор позиции, неизвестное имя позиции, неверное число аргументов и неquoted значения. Повторные `phead` и `pfoot` независимо используют последнее целое expression в порядке ANTa/ANTz и shared `INCL` merge. `DocumentFixedPagePresentation.PrintedHeader/PrintedFooter` сохраняют значения для вывода на печать: HTML содержит три экранированных spans внутри print-only header/footer вне SVG image, по умолчанию они скрыты `display:none`; `@media print` размещает их в трёхколоночном CSS grid с исходным left/center/right выравниванием. Print annotations не изменяют экранный raster, source zoom, selectable text, ссылки и не внедряют raw HTML. Известные malformed `phead/pfoot` завершаются ошибкой.

Vendor-specific и неизвестные DjVu annotation expressions не получают предположительной интерпретации. `DjvuAnnotationReader` сохраняет точное имя и область каждого неизвестного выражения: `TopLevel`, `MapAreaShape` или `MapAreaOption`. В `ANTa`/`ANTz` и shared `INCL` merge диагностические записи сохраняют исходный порядок, без содержимого неизвестного payload. Неизвестная shape не создаёт ложную интерактивную область; неизвестная option не влияет на известные visual properties той же maparea; недопустимая известная option продолжает завершаться ошибкой. Для каждой annotation chunk действует лимит 10 000 неизвестных выражений, после merge — 100 000. `DocumentFixedPagePresentation.UnrecognizedAnnotations` сохраняет записи для анализа; `ParserTrace` и HTML `data-unrecognized-annotation-count` выводят только количество. Имена и raw payload не внедряются в HTML, поэтому расширения с HTML-подобными именами не исполняются. Для реальной реализации нового vendor-specific behavior нужны документация расширения и подтверждающий fixture.

Reader разбирает все пять стандартных `maparea` shapes: `rect`, `oval`, `poly`, `text` и `line`, сохраняет optional `(url href target)` metadata и точную bottom-left pixel geometry. Visual profile maparea поддерживает `none`, `xor`, `border`, `shadow_in/out/ein/eout`, `border_avis`, rectangular `hilite` + `opacity` (0–100, default 50), line `arrow`/`width`/`lineclr` и text `backclr`/`textclr`/`pushpin`; повторные известные options применяются последовательно с last-value-wins. Colors принимаются только как `#RRGGBB`; option, применённая к недопустимой shape, завершается явной ошибкой. Fixed-page renderer сохраняет decorative mapareas с пустым URL, рисует XOR через white stroke + `mix-blend-mode:difference`, solid/hover/always borders, shadow modes через CSS inset/outset/groove/ridge, highlights с source opacity, colored lines и optional arrow marker, а text notes — через XHTML `foreignObject`; pushpin использует нативный `details/summary` без JavaScript. Размер arrow marker и font/layout text note определяются renderer-ом, поскольку DjVu source задаёт наличие arrow и цвета/область текста, но не отдельные arrowhead/font metrics.

`TXTa` и BZZ-compressed `TXTz` извлекают strict UTF-8 page text. Version-1 text-zone tree разбирает PAGE/COLUMN/REGION/PARAGRAPH/LINE/WORD/CHARACTER geometry и UTF-8 byte ranges. `DjvuTextOverlayBuilder` берёт terminal zones без дублирования parent ranges, сохраняет исходные UTF-8 gaps между соседними zones, строго отклоняет split-codepoint/overlap boundaries и создаёт transparent `DocumentFixedTextRun` overlay. Непустые OCR zones могут выходить за `INFO` bounds, как допускает DjVu text model: координаты не clamp-ятся и не отбрасываются, а SVG viewport скрывает внешнюю часть; interactive maparea geometry остаётся строго page-bounded. Общий SVG renderer использует точную zone width через `textLength/spacingAndGlyphs`, top-aligned geometry, INFO rotation и `user-select:text`; последовательность run text точно восстанавливает `DocumentFixedPage.Text`. Ctrl+F не перехватывается fullscreen hotkey и передаётся WebView2 с включёнными browser accelerator keys.

Resource limits ограничивают file/chunk/nesting/dependency counts, annotation token/depth/chunk counts, parsed ANTa metadata/maparea counts, METa/METz decoded payload/chunk/page/document bounds, unrecognized annotation expression count, unrecognized page chunk count, decoded BZZ/IW44/JB2/blank raster sizes, shapes/blits/comments, page count, суммарный indirect component input и PNG payload fixed-page model. Неизвестные page chunks не принимаются за blank image; неизвестные/конфликтующие visual layer families, duplicate local `Djbz`, cyclic/too-deep shared dependency graphs, striped `Smmr`, malformed known annotations и недопустимые значения завершаются явной ошибкой вместо частичного рендера.

Regression покрывает container/DIRM/NAVM/text/annotation parsing, top-level background/zoom/mode/alignment/metadata/XMP merge semantics, DjVu 3 print-only phead/pfoot parsing/merge и screen-hidden/print-only HTML с entity escaping, page-local METa/METz binary/BZZ metadata preservation и safe HTML count, scoped diagnostics неизвестных top-level/maparea-shape/maparea-option expressions, ANTa/ANTz order, resource limit и HTML safety, active page-scoped zoom/align для всех пяти zoom kinds и native/physical CSS geometry, pixel-accurate foreground/background/BW source display modes и reader → mode-specific PNG, все пять стандартных maparea shapes и visual options, visual-only empty-URL annotations, hover/always borders, hilite opacity, line color/arrow, text pushpin, bundled/indirect nested shared dependencies и cycle rejection, external `SourcePath` binding, local-vs-included JB2 dictionary precedence, JPEG/IW44/JB2/Smmr decoding, FGbz, compound composition, reader → `DocumentModel` → PNG/text/annotation/presentation → HTML/SVG, rotation geometry, out-of-page OCR zones, UTF-8 boundaries, traversal/role/size errors и malformed input. Синтетический regression с последовательными ANTa и BZZ-сжатым ANTz проверяет полный `reader → DocumentFixedPagePresentation → @media print HTML` для phead/pfoot, включая наследование footer, replacement header и безопасное экранирование HTML-like текста. В расширенном локальном наборе 26 успешно разобранных DjVu-документов / 503 страниц с 165 annotation chunks не обнаружено ни реальных phead/pfoot, ни неизвестных extension expressions; эти paths проверяются отдельно по DjVu 3 specification и синтетическим ANTa/ANTz fixtures, а не заявляются подтверждёнными real corpus. Основной real validation corpus содержит 7 корректных DjVu файлов / 147 страниц; четыре legacy fixtures с некорректным UTF-8 внутри `TXTz` завершаются строгой `InvalidDataException`, без producer-specific byte fallback. Дополнительно real `boy_jb2.djvu`, подключённый как external page через indirect DIRM index, проходит полный reader/render path. Real bundled `czech.djvu` проходит 85-page reader/render: 83 text-bearing pages, 49 areas, 30 XOR borders, metadata на всех 85 страницах и `background #8F8F8F` на трёх страницах; HTML содержит ровно три surrounding-background hints и 85 metadata-count markers. Real `vega.djvu` проходит 2/2 pages с `zoom d100` и `mode color`, а `DjVu3Spec_bundled.djvu` — 71/71 pages с `mode color`; neutral model и HTML сохраняют эти значения. Real `navm_fgbz.djvu` проходит 6-page reader/render с 20 XOR areas и 20 corresponding difference-mode SVG borders. `malliavin.djvu` проходит полный reader/render path на 115/115 страницах: 114 text-bearing pages, 2 visual-only empty-URL rect areas с 32-pixel `shadow_in/out`, `hilite #C0FFFF` и default 50% opacity, 30 849 851 bytes encoded PNG. Страница 6 содержит только `INFO` и рендерится как opaque white 2862×4916 surface; HTML содержит два highlights, один inset и один outset visual border. Real legacy fixtures `legacy_pm44.djvu` и `legacy_bm44.djvu` проходят полный one-page reader/render path: PM44 — color IW44 v1.2, 181×240, 100 DPI; BM44 — grayscale IW44 v1.2, 32×32, 100 DPI. Их BGRA32 outputs SHA-256 regression-locked; synthetic bundled и indirect DIRM role-1 fixtures проверяют routing `FORM:PM44` и external `SourcePath`. Real BG44 + Sjbz + FGbz page 10 из `2000_compression_system.djvu` имеет фиксированные SHA-256 для `fore` (`B6FEDDCB33C7E08184226D95DD5BBA5EC2641AB8D36E84ADE9043F0CD669E82F`), `back` (`1D3607977837E155644210162F7B720E99F8C2DAF08B5C7D9E652D53F3D6D2E1`) и `bw` (`1C96524206F2DE57EC70297888E1BAE9A47E9B87BEEF7BAD31108A7C7021BD9B`); synthetic Smmr + BGjp + FGjp проверяет каждый pixel по отдельно декодированным layer/mask и все четыре `mode` через полный reader → PNG. Отдельный registry regression копирует реальный PM44 fixture в `.iw4` и проходит `SupportedFormatRegistry → DjvuDocumentReader → DocumentFixedPage`, поэтому standalone legacy extension доступен через обычный open/file-association path. `BG2k`/`FG2k` не входят в профиль: актуальный DjVuLibre помечает соответствующий JPEG-2000 bitstream как not finalized и не декодирует эти chunks.

## Readiness gates

Перед выпуском профиля выполняются следующие проверки:

- Release build без warnings/errors.
- Полный regression suite.
- Все поддерживаемые файлы из локального `Books` corpus открываются; reader-backed
  документы дополнительно проходят полный `reader -> DocumentModel -> HTML renderer` путь.
- DOC/PDF проходят детерминированный malformed-input набор.
- Входные файлы имеют общий размерный предел; EPUB/DOCX имеют limits на ZIP entries,
  размер распакованных parts и compression ratio.
- XML для FB2/EPUB/DOCX читается без обработки DTD и внешних сущностей и с
  ограничением размера XML.
- RTF nesting и PDF page-tree nesting ограничены.
- Декодированные PDF Flate/LZW/RunLength streams имеют отдельный предел.
- Unsupported конструкции, для которых нельзя гарантировать корректную
  интерпретацию, завершаются явной ошибкой вместо приблизительного рендера.

## Known fidelity limits

Эти пункты не блокируют обычное чтение, но остаются backlog для расширения
совместимости и точности.

### DOCX

- Нет полноценного pagination/page-layout engine; документ читается как flow content.

### DOC

- Редкие list/table style и locale-specific numbering variants.
- Часть редких OfficeArt connector/fill/arrow presets.
- Некоторые header/footer, note, field и section layout semantics требуют
  полноценного pagination engine.
- Legacy Symbol/OEM byte mapping и старые до-Word-97 Binary variants не входят
  в готовый профиль.
- Нет полноценного pagination/page-layout engine.

### RTF

- Редкие row/cell и paragraph controls; row index/banding, last-row marker, table indent units и документированные Word table-look flags для borders/shading/font/color/best-fit, first/last row/column и banding уже сохраняются как metadata.
- Scale без goal-size использует только явно сохранённую PNG/JPEG/BMP physical-density metadata; при её отсутствии размер не угадывается. Bitmap `wbmbitspixel`/`wbmplanes`/`wbmwidthbytes` сохраняются как metadata; `wbitmap`, `macpict` и OS/2 Presentation Manager metafile явно помечены unsupported до появления точных decoder'ов. Отрицательное picture crop-extension пока сохраняется без layout/canvas расширения.
- Редкие charset/codepage combinations за пределами точных известных mappings.
- Некоторые декоративные border styles имеют CSS fallback, а не pixel-identical Word rendering.

### PDF

- PDF Image XObject `/ImageMask true` использует stencil semantics: 1-bit samples с row padding, `/Decode [0 1]` и `[1 0]`, текущий nonstroking RGB color на каждом `Do` и RGBA output с прозрачностью. Для bilevel CCITT/JBIG2 используется их 8-bit decoded sample path. Дополнительные `/Mask` и `/SMask` для stencil отклоняются; stencil DCT/JPX не входят в профиль.
- ExtGState soft-mask group compositing не реализован полностью. Проверяются известные `/SMask /S` (Alpha/Luminosity) и тип `/G` (Form XObject stream); дополнительно проверяются `/BBox` (четыре конечных числа, положительная площадь), а `/Matrix` — шесть конечных компонентов с невырожденной линейной частью и `/Group /S /Transparency` у Form XObject `/G`. Словарь `/SMask` без обязательного `/G` теперь отклоняется `InvalidDataException` (вместо вывода без маски); для корректных `/SMask /G` с transparency group применяется явный `NotSupportedException` вместо молчаливого вывода без маски. `/SMask /TR` c не-Identity transfer и `/SMask /BC` явно отклоняются как unsupported (negative regressions), не игнорируются. Это не рендеринг transparency group.
- Predefined Type0 CMaps для public Adobe CJK/KR collections входят в профиль: canonical Adobe resources дают code→CID, включая `usecmap` inheritance; без `/ToUnicode` CID→Unicode берётся из canonical `Registry-Ordering-UCS2` mapping resources.
- CIE-based raster ColorSpace `CalGray`, `CalRGB` и `Lab` входят в профиль для 8-bit decoded samples с точными PDF gamma/matrix/Lab transforms и chromatic adaptation к sRGB. `CalGray` DCT входит в профиль через grayscale sample decode; `CalRGB` DCT — при effective JPEG `ColorTransform=1`, с приоритетом Adobe APP14 marker над `/DecodeParms /ColorTransform`. CIE `/SMask /Matte` входит в профиль с unpremultiply в исходных CIE components до gamma/matrix/Lab conversion. `Lab` DCT и `CalRGB` DCT с effective transform=0 поддерживаются через managed BitMiracle.LibJpeg.NET raw-component decoder (JCS_UNKNOWN), который отключает JPEG color conversion, проверяет geometry и ограничивает decoded raster 256 MiB. `ICCBased` `/N=1/3/4` входит в профиль через embedded ICC profile и системный WPF ICC/ICM engine; `/Range` и `/Decode` учитываются строго. ICC Gray/RGB/CMYK DCT post-processing входит в профиль, причём `/N=4` использует decoded CMYK JPEG samples до ICC conversion. `Separation` и `DeviceN` входят в профиль через общий PDF Function evaluator: `FunctionType 2`, sampled `FunctionType 0` с multilinear `/Order=1` и stitching `FunctionType 3`; alternate DeviceGray/DeviceRGB/DeviceCMYK поддерживаются. `FunctionType 4` calculator functions входят в профиль через отдельный VM с полным разрешённым operator set, PDF numeric grammar, 32-bit integer semantics и overflow promotion, PostScript round/bitshift/cvi behavior, синтаксическими conditional expressions для `if`/`ifelse`, top-N output stack semantics, строгими type/stack checks и resource limits. Sampled `FunctionType 0` `/Order=3` входит в профиль через Acrobat-compatible multidimensional cubic interpolation с cubic-convolution `a=-0.5`, quadratic edge handling и recursive interpolation по измерениям. ICCBased, Separation и DeviceN `/SMask /Matte` входят в профиль с unpremultiply в исходных component/tint coordinates до ICC profile conversion или tint transform. DeviceCMYK DCT post-processing входит в профиль через 8-bit CMYK sample decode с geometry validation и последующим PDF `/Decode`. Ненулевой CIE BlackPoint остаётся вне профиля. DeviceN+DCT не заявляется как поддерживаемый: PDF DCT profile ограничен максимум четырьмя components, поэтому произвольный N-channel JPEG не эмулируется.
- CCITT Group 3/Group 4, `JPXDecode` и `JBIG2Decode` входят в профиль. JPX декодируется pure-managed CoreJ2K 2.4.1.108 с geometry/component validation и decoder resource limits; PDF `/BitsPerComponent` и `/Decode` для JPX не используются, явный PDF `/ColorSpace` имеет приоритет над embedded JPX color mapping, а при отсутствии `/ColorSpace` используются embedded Gray/RGB/CMYK semantics. JBIG2 декодируется pure-managed SharpAstro.Jbig2 3.16.981 с optional `/JBIG2Globals`, строгим `/BitsPerComponent 1`, 256 MiB raster limit и обычным PDF `/Decode` после reconstruction. Поддержан arithmetic/MMR surface; Huffman-coded symbol/text variants, custom Huffman tables, MMR внутри pattern/halftone, HENABLESKIP и TPGRON остаются явным unsupported; synthetic SDHUFF regression проверяет NotSupportedException, а PDF adapter сохраняет контекст JBIG2Decode в диагностике. JPX RGB+alpha alpha-first `cdef` дополнительно проверяется end-to-end PDF→PNG pixel regression; alpha на позициях 1 и 2 теперь поддерживается: исходные компоненты читаются без embedded color mapping и переставляются по JP2 cdef; проверяется samples и конечный PDF→PNG BGRA; дополнительно покрыт `/SMaskInData=2` с `/Matte` и проверкой фактических пикселей для обеих средних позиций alpha. JPX JP2 `cdef` для embedded opacity проверяется: для Gray+alpha с alpha-first `cdef` выполняется нормализация метаданных перед CoreJ2K и перестановка decoded samples; для RGB+alpha (четыре компонента) с alpha-first `cdef` также выполняется нормализация JP2 metadata и перестановка RGBA samples; произвольные другие перестановки остаются unsupported. JPX с неявным Gray+alpha (два компонента) поддерживает `/SMaskInData=1` и `/SMaskInData=2` с точной Gray `/Matte` compensation; оба варианта покрыты end-to-end regressions. JPX `/SMaskInData=1` входит в профиль: embedded unassociated opacity извлекается из JPX alpha component и кодируется вместе с цветом в RGBA PNG; поддерживаются явный `/DeviceRGB` и embedded sRGB, а также согласованные компоненты остальных реализованных PDF ColorSpace. Проверяются alpha channel metadata и component counts. JPX `/SMaskInData=2` с preblended colors поддерживается для DeviceGray/DeviceRGB с обязательным `/Matte`: compensation выполняется в исходных цветовых компонентах до RGBA encoding. Для CalGray/CalRGB/Lab и ICCBased компенсация выполняется в исходных компонентах после PDF component decoding и до CIE/ICC преобразования; подтверждены end-to-end CalRGB и ICCBased RGB. Separation и DeviceN также компенсируют tint-компоненты до FunctionType tint transform; end-to-end JPX regressions покрывают Separation/FunctionType 2 и DeviceN/FunctionType 4. Indexed также поддерживает `/SMaskInData=2`: компенсация palette index выполняется до RGB lookup, с проверкой длины `/Matte`; покрыто end-to-end JPX regression.
- Revision 5/6 Unicode passwords проходят SASLprep на фиксированных Unicode 3.2 tables, UTF-8 и truncation до 127 bytes; R6 user/owner authentication использует Algorithm 2.B hardened hash и AESV3. Legacy revisions сохраняют точный byte-password API.
- Password-protected PDF открывается через локализованный password prompt; неверный пароль запрашивается повторно, пароль не сохраняется. R2-R4 string passwords кодируются точным PDFDocEncoding, R5/R6 — SASLprep/UTF-8.
